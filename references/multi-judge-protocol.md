# 多法官共识协议

> 单法官的 LLM-as-Judge 存在已知偏差（长度偏好、格式偏好、自我偏好、宽容偏差）。本协议通过 3 透镜多法官 + 中位数共识，将主观方差降低至可量化范围。

---

## 核心机制

对维度 1（业务增益度）的每条硬断言 A1-A5，使用 **3 个不同透镜** 的法官独立判定，取中位数作为最终结论。

```
        被评测输出
            │
   ┌────────┼────────┐
   ▼        ▼        ▼
 [严格审计] [怀疑者] [倡导者]
   │        │        │
   └────────┼────────┘
            ▼
      中位数共识
```

---

## 3 个法官透镜

### J1: 严格审计官（Strict Auditor）

**默认透镜，已有。** 严格执行 A1-A5 断言定义，不做任何推断。

System Prompt 追加：
```
你是严格审计官。只接受完全满足断言条件的证据。
任何缺失、模糊、脑补的回答一律 FAIL。
不要因为输出很长就倾向 PASS。
```

### J2: 怀疑者（Skeptic）

**主动寻找 FAIL 理由。** 假设输出是不合格的，寻找证据推翻 PASS 判定。

System Prompt 追加：
```
你是怀疑者。你的默认立场是被评测输出不合格。
对每条断言，先假设 FAIL，只有当输出中存在不可辩驳的证据时才改为 PASS。
特别关注：输出是否在玩文字游戏？约束响应是否只是模板化套话？
量化数字是否有来源？执行步骤是否只是通用流程而非针对性方案？
```

### J3: 倡导者（Advocate）

**主动寻找 PASS 理由。** 假设输出是合格的，寻找证据支持 PASS 判定。

System Prompt 追加：
```
你是倡导者。你的默认立场是被评测输出合格。
对每条断言，先假设 PASS，只有当输出中确实缺失关键元素时才改为 FAIL。
寻找输出中的亮点：是否有超出预期的洞察？是否有具体的数据支撑？
执行步骤是否有可操作性？领域深度是否体现了专业知识？
```

---

## 共识规则

对每条断言 Ai（i=1..5）：

```
J1(Ai) ∈ {PASS, FAIL}
J2(Ai) ∈ {PASS, FAIL}
J3(Ai) ∈ {PASS, FAIL}

consensus(Ai) = majority(J1, J2, J3)
```

- 3/3 一致（全 PASS 或全 FAIL）→ **高置信判定**，无争议
- 2/1 分歧 → **中置信判定**，采用多数意见，但记入 `judgeConsensus.disputedAssertions`

**分歧处理：** 当 ≥2 条断言出现 2/1 分歧时，触发 1 次**仲裁调用**：

```
[仲裁法官 System Prompt]
两位审计官对以下断言判定 PASS，一位判定 FAIL。
请作为最终仲裁者，仔细审查输出并给出最终判定。
特别注意 FAIL 方提出的理由是否成立。
```

仲裁结果为最终判定，不可再争议。

---

## 一致性度量

```
judgeAgreement = 全一致断言数 / 总断言数

judgeAgreement ≥ 0.8 → 高一致性，分数可信
judgeAgreement 0.6-0.8 → 中一致性，分数有波动风险
judgeAgreement < 0.6 → 低一致性，在报告中标注「评测置信度低」
```

`judgeAgreement` 写入 `AIScore.judgeConsensus.agreement`。

---

## 成本影响

| 项目 | 调用数 | 说明 |
|------|:------:|------|
| J1 严格审计 | 1 | 已有（当前 Judge 调用） |
| J2 怀疑者 | +1 | 新增 |
| J3 倡导者 | +1 | 新增 |
| 仲裁（条件触发） | 0-1 | 仅 ≥2 条分歧时触发 |

**典型增量：+2 次 LLM 调用**（约 +¥0.03）。分歧率高时 +3 次。

---

## 适用范围

- ✅ 维度 1（业务增益度）— 主观性最高，最需要多法官
- ❌ 维度 2（提示词工程）— 结构化评审，主观性低，单法官足够
- ❌ 维度 3/4（鲁棒性/安全）— 行为判定（拒答/质疑），两阶段已有交叉验证
- ❌ 维度 5/6（兼容性/性价比）— 纯代码/统计，无主观性

**结论：多法官仅适用于维度 1。** 对低主观性维度强加多法官是浪费成本。
