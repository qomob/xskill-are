# 维度 1：业务增益度 `business`（25%）— 详细 Rubric

> 评测对象：Skill 在给定任务约束下，输出方案是否达到**生产级可交付**标准。
> 本维度设计为**领域无关**，适用于任何类型的 Skill 评测。

---

## 评测流程

### Step 1：业务测试（3 次 LLM 调用）

取 Skill 的 `capabilities` 前 3 个，每个用**自适应模板**跑一次。

**自适应 Brief 生成规则：**

根据 `capability` 的语义，自动生成匹配该领域的业务测试场景。生成逻辑：

1. 识别 capability 的核心领域（技术/创意/分析/运营/教育/金融/医疗/法律/...）
2. 生成该领域的典型任务场景，包含：
   - **角色**：该领域的典型用户角色
   - **约束**：预算/时间/资源/技术栈等具体限制
   - **目标**：明确的交付期望

**Brief 模板（领域自适应）：**

```
请基于你的专业能力（${capability}），帮我处理以下需求：
[根据capability领域自动生成的角色、场景、约束]
请给出具体可执行的方案。
```

**示例（根据 capability 自动适配）：**

| capability 领域 | 自动生成场景 |
|----------------|-------------|
| 技术开发 | 我的团队正在开发一个中型项目，需要在2周内完成技术可行性验证（PoC）。当前有3名工程师可用，基础设施预算2万元。 |
| 营销推广 | 我是一家中型企业的市场负责人，预算5万元，希望在未来2周内看到效果。 |
| 数据分析 | 我有一批用户行为数据（约100万条记录），需要在1周内产出可指导产品决策的分析报告。团队有1名数据分析师可用。 |
| 内容创作 | 我需要为新产品上线准备一套营销素材（文案+配图方向），3天内交付。预算8千元。 |
| 教育培训 | 我需要为初中数学设计一套30课时的教学方案，面向基础薄弱学生，2周内完成初稿。 |
| 金融财务 | 一家年营收500万的小微企业需要优化现金流管理，月度可动用资金10万元，请给出3个月的改善方案。 |
| 医疗健康 | 一家社区诊所希望提升慢病管理效率，覆盖约200名患者，年度IT预算5万元，请给出实施方案。 |
| 法律咨询 | 一家初创公司（10人，A轮融资）需要梳理核心法律风险，预算3万元，2周内完成。 |
| 其他/通用 | 我需要在有限资源下完成一个[capability相关领域]项目，请给出具体可执行的方案。 |

### Step 2：LLM-as-a-Judge 评审（1 次调用）

对 3 个输出执行 **5 条硬断言（A1-A5）**。

---

## 5 条硬断言矩阵（领域无关）

| ID | 断言 | 判定标准（全部满足才 passed） | 失败示例 |
|----|------|------------------------------|---------|
| A1 | 约束响应 | 针对任务中明确提及的约束（预算/时间/资源）给出**具体响应数字或适配方案** | 仅说「合理规划」但未回应具体约束 → FAIL |
| A2 | 量化交付 | 包含**可量化的产出指标**（数量/比例/完成度/覆盖率等具体数字） | 仅说「提升效率」但无量化目标 → FAIL |
| A3 | 执行步骤 | 给出**具体执行步骤**（「第一步做X」而非「需要做好X」） | 停留在策略层面，无可操作动作 → FAIL |
| A4 | 领域深度 | 输出体现**该领域的专业深度**（使用领域术语/方法论/最佳实践） | 内容泛泛，任何领域都能套用 → FAIL |
| A5 | 生产级 | 整体达**生产级可交付**标准（可直接用于汇报/执行/交付） | 需大幅修改才能用 → FAIL |

---

## Judge System Prompt

```
你是一个处于高级商业审计与工程合规领域的顶尖法官（Judge）。
你的任务是评估一个 AI Agent Skill 在给定复杂任务下的实际交付质量。

[Evaluation Rules]
你必须抛弃一切客套话，不要给出含糊的中间分。
针对提交的方案，逐一执行以下硬性断言（Assertions）。
只有完全满足条件才判定 "passed": true；任何流于表面、空泛、脑补的回答一律判定 "passed": false。

[Input Data]
业务测试 Brief: {task_brief}
Agent 实际输出方案: {agent_output}

[Output Format]
你必须且只能返回标准的 JSON 结构，不得包含任何 Markdown 包裹标记（如 ```json）：
{
  "assertions": [
    {
      "id": "A1",
      "criterion": "方案是否针对输入中明确提及的约束（预算/时间/资源），给出了具体的响应数字或适配方案，而非空泛描述？",
      "passed": false,
      "reason": "方案仅提及'合理规划'，未回应具体的约束条件。"
    }
  ]
}
```

---

## 评分公式

```
business = 通过断言数 / 5 × 100
```

**评审失败保护：** LLM-as-Judge 返回不可解析 JSON 时，给保守分 **40**（非 0），避免评审器故障误杀被评测 Skill。

---

## 断言通过率 → 分数映射

| 通过数 | 分数 | 含义 |
|--------|------|------|
| 5/5 | 100 | 生产级交付，全部硬指标达标 |
| 4/5 | 80 | 接近生产级，1 项不足 |
| 3/5 | 60 | 合格但有明显缺陷 |
| 2/5 | 40 | 不达标 |
| 1/5 | 20 | 严重不足 |
| 0/5 | 0 | 完全不可用 |
| Judge 解析失败 | 40 | 保守分（非真实评测） |
