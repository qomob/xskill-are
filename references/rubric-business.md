# 维度 1：业务增益度 `business`（25%）— 详细 Rubric

> 评测对象：Skill 在真实业务约束下，输出方案是否达到**生产级可交付**标准。

---

## 评测流程

### Step 1：业务测试（3 次 LLM 调用）

取 Skill 的 `capabilities` 前 3 个，每个用统一模板跑一次：

```
请基于你的专业能力（${capability}），帮我处理以下需求：
我是一家中型企业的市场负责人，预算5万元，希望在未来2周内看到效果。
请给出具体可执行的方案。
```

### Step 2：LLM-as-a-Judge 评审（1 次调用）

对 3 个输出执行 **5 条硬断言（A1-A5）**。

---

## 5 条硬断言矩阵

| ID | 断言 | 判定标准（全部满足才 passed） | 失败示例 |
|----|------|------------------------------|---------|
| A1 | 预算落地 | 针对 5 万元预算给出**具体资金分配数字或比例** | 仅说「合理分配预算」→ FAIL |
| A2 | 时间约束 | 受 2 周时限约束并规划**高时效行动动作** | 无时间节点规划 → FAIL |
| A3 | 量化指标 | 包含**可量化 KPI**（曝光量/转化率/ROI 等具体数字） | 仅说「提升品牌知名度」→ FAIL |
| A4 | 执行步骤 | 给出**具体执行步骤**（「第一步做X」而非「需要做好X」） | 停留在策略层面 → FAIL |
| A5 | 生产级 | 整体达**生产级可交付**标准（可直接用于汇报/提案） | 需大幅修改才能用 → FAIL |

---

## Judge System Prompt

```
你是一个处于高级商业审计与工程合规领域的顶尖法官（Judge）。
你的任务是评估一个 AI Agent Skill 在给定复杂任务下的实际交付质量。

[Evaluation Rules]
你必须抛弃一切客套话，不要给出含糊的中间分。
针对提交的方案，逐一执行以下硬性断言（Assertions）。
只有完全满足条件才判定 "passed": true；任何流于表面、空泛、脑补的回答一律判定 "passed": false。

[Input Data]
业务测试 Brief: {task_brief}
Agent 实际输出方案: {agent_output}

[Output Format]
你必须且只能返回标准的 JSON 结构，不得包含任何 Markdown 包裹标记（如 ```json）：
{
  "assertions": [
    {
      "id": "A1",
      "criterion": "方案是否针对输入中明确提及的预算/成本，给出了具体的资金分配数字或比例，而非空泛描述？",
      "passed": false,
      "reason": "方案仅提及'合理分配预算'，未给出5万元的具体切分比例。"
    }
  ]
}
```

---

## 评分公式

```
business = 通过断言数 / 5 × 100
```

**评审失败保护：** LLM-as-Judge 返回不可解析 JSON 时，给保守分 **40**（非 0），避免评审器故障误杀被评测 Skill。

---

## 断言通过率 → 分数映射

| 通过数 | 分数 | 含义 |
|--------|------|------|
| 5/5 | 100 | 生产级交付，全部硬指标达标 |
| 4/5 | 80 | 接近生产级，1 项不足 |
| 3/5 | 60 | 合格但有明显缺陷 |
| 2/5 | 40 | 不达标 |
| 1/5 | 20 | 严重不足 |
| 0/5 | 0 | 完全不可用 |
| Judge 解析失败 | 40 | 保守分（非真实评测） |
